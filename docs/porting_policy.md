# 移植策略

1. **范围**：只移植性能/调度相关能力（sched_assist、frame_boost、uad、task_*、sched_info），不做无关驱动。
2. **形态**：先以 GKI 供应商模块形态移植（只用导出符号与 `android_vh_*` 钩子）；确实缺符号时再考虑 in-tree graft，且 graft 必须能回退。
3. **禁止半成品**：一个模块要么完整可用，要么不加载；不允许"部分节点存在但语义不对"长期停留。
4. **KMI**：不修改导出符号签名、不移动导出结构字段；任务字段走 `ANDROID_KABI_RESERVE`。
5. **可观测**：每个模块都要能在 `lsmod`、`/proc/oplus_*`、logcat 三处确认状态；失败要打一条明确日志（不刷屏）。
6. **可回滚**：试水阶段保证 `rmmod` 干净退出；进内核阶段随 boot 镜像回滚。
7. **实测优先**：任何"应该更快"的判断都要有交替 A/B 数据；单项改动至少 4 对样本。
